## 知识资产诊断：先交付四张清单 {#diagnosis}

<p>诊断不是一次泛泛交流。我们会围绕一个优先业务场景，对现有资料、真实问题、可复用内容和风险缺口进行结构化盘点，让企业在正式搭建前先看清起点。</p>

<div class="diagnosis-deliverables">
  <article><span>01 / ASSETS</span><h3>知识资产清单</h3><p>识别已有文章、案例、项目文件、问答、产品资料、SOP与经验记录，判断来源、状态和可用价值。</p><b>回答：企业已经拥有什么？</b></article>
  <article><span>02 / SCENARIOS</span><h3>高频问题与业务场景清单</h3><p>梳理团队反复查找、反复回答和高度依赖个人经验的任务，并按频率、价值和实施难度确定优先级。</p><b>回答：应该先解决什么？</b></article>
  <article><span>03 / MATERIALS</span><h3>可复用素材清单</h3><p>从真实资料中识别可转成客户答疑、案例证据、内容选题、销售表达、方法步骤和培训材料的素材。</p><b>回答：哪些内容可以马上创造结果？</b></article>
  <article><span>04 / GAPS</span><h3>风险、过期与知识缺口清单</h3><p>标记来源不明、版本冲突、重复过期、权限敏感、口径不一致和关键资料缺失等问题。</p><b>回答：哪些内容不能直接使用？</b></article>
</div>

<div class="diagnosis-scope">
  <div><span>诊断完成后</span><b>明确首个试点场景、建议的7库映射、需补资料和项目验收重点。</b></div>
  <div><span>诊断不等于完整搭建</span><b>企业定制目录、字段模板、权限审核、工作流配置、培训和移交属于后续项目交付。</b></div>
</div>

## 从诊断到是否立项 {#process}

<div class="diagnosis-process">
  <article><span>01 / PREPARE</span><h3>确定优先场景</h3><p>只选择一个高频、高价值、可验证的任务，并确认参与人和资料范围。</p><b>产出：诊断范围说明</b></article>
  <article><span>02 / INVENTORY</span><h3>盘点资料与问题</h3><p>识别已有资产、重复任务、可复用素材，以及来源、权限、版本和知识缺口。</p><b>产出：四张诊断清单</b></article>
  <article><span>03 / DECIDE</span><h3>形成架构判断</h3><p>判断采用完整7库、最小试点、业务域、流程、部门权限或混合结构。</p><b>产出：知识架构决策记录</b></article>
  <article><span>04 / PROPOSE</span><h3>决定是否立项</h3><p>明确试点、交付范围、责任人、验收方法和暂不纳入项，再评估项目报价。</p><b>产出：实施建议与范围边界</b></article>
</div>

## 准备诊断前，先做四项自检

<div class="diagnosis-grid">
  <div><span>01</span><h3>你有真实业务任务吗？</h3><p>例如持续内容、客户答疑、销售方案、交付 SOP 或团队培训。</p></div>
  <div><span>02</span><h3>你有可盘点的资料吗？</h3><p>不要求整理完，但至少有文章、笔记、对话、案例或项目文档。</p></div>
  <div><span>03</span><h3>你愿意参与人工审核吗？</h3><p>系统可以提高调用和生成效率，但事实、判断与授权不能外包给 AI。</p></div>
  <div><span>04</span><h3>你最想先改善哪个结果？</h3><p>一次只选一个主场景，最容易跑通并形成可验证的闭环。</p></div>
</div>
