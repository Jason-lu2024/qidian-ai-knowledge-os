## 完整案例应该如何被讲清楚 {#full-case}

<section class="full-case">
  <div class="full-case-head"><div><span>DEMO CASE / 01</span><h2>一人公司：从散乱资料到稳定内容生产</h2></div><em>演示案例 · 非真实客户成果</em></div>
  <div class="case-story-grid">
    <article><span>01 / 背景</span><h3>有资料，但没有稳定调用路径</h3><p>历史文章、咨询问答、朋友圈片段和课程笔记分散存放。每次写内容仍从空白页开始。</p></article>
    <article><span>02 / 盘点</span><h3>先分清方向、问题、素材与标准</h3><p>把已确认定位放入定位库；客户原话进入问题库；故事和证据进入素材库；优质历史文章进入高分样本库。</p></article>
    <article><span>03 / 联动</span><h3>从一个问题启动，而不是让 AI 猜</h3><p>AI 读取定位边界、客户问题、相关素材与样本风格，输出提纲和初稿，同时标记缺失证据。</p></article>
    <article><span>04 / 审核</span><h3>人负责事实、判断与最后表达</h3><p>检查是否属于核心客户、案例是否授权、观点是否真实，再决定发布或退回补充资料。</p></article>
  </div>
  <div class="evidence-note"><b>本案例若转为真实发布，至少需要：</b><span>授权状态</span><span>原始资料清单</span><span>流程截图</span><span>人工修改记录</span><span>可核验结果</span><span>失败与限制</span></div>
</section>

## 案例证据应该包含什么

<div class="evidence-grid"><article><b>输入证据</b><p>资料来源、版本、授权状态，以及使用了哪些知识库。</p></article><article><b>过程证据</b><p>提示词或 Skill、人工判断点、迭代过程与失败情况。</p></article><article><b>结果证据</b><p>可查看的产出、前后对比、时间或质量标准，不使用模糊宣传词。</p></article><article><b>边界说明</b><p>哪些结果由人完成、哪些不可复现，以及场景限制。</p></article></div>
